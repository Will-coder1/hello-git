# 新人上手指引（学长留，走之前写的，比较仓促）

> 交接得很急，有些事我处理了但没写清楚。这份不当事清单用，当**方向**用。
> 别指望它告诉你东西在哪 —— 我只写"我碰过什么"，找不找得到看你自己的本事。

---

## 一、先建立三个习惯

1. **别只在网页上点。** 网页是给眼睛看的，`git` 是给手用的。很多真相需要 `clone` 之后才看得到。
2. **你看到的是"某一刻"，不是"全部"。** 文件是某一刻快照，分支是某一刻的指针，网页是某一刻的渲染。
3. **"清理"和"删除"是两件事。** 每次有人跟你说"我把东西删干净了"，先在心里问一句：删的是文件、提交、分支，还是日志？

## 二、我碰过的地方（顺序不定，别按编号找）

交接前我确实收拾过一遍，但**不保证干净**。下面六件事我大概动过，各留了一点痕迹：

| 我做过什么 | 大致方向 |
|---|---|
| 收拾过机器上的一些老配置 | 仓库里跟"环境/机器"沾边的那一小块 |
| 清掉过一个内部的调试标记 | 有提交说过"移除"，那就去看看它移除了什么 |
| 开过一次分支，后来没收尾 | 现在分支列表里看不到它了，但它开过的地方还留着 |
| 让自动检查跑过一次 | 那次是红的 —— 红的才有人认真看 |
| 写过一页文档，后来删了 | 文档区现在看着是空的 |
| 跟人聊的时候提过一嘴 | 不是代码，是"对话"留下的东西 |

> 这六条**不是六个步骤**，是六种"处理方式"。同一种方式可能对应不止一处，也可能有的根本没有。

## 三、关于编号

我在每处都留了 `partX` 这样的编号。**编号只说明拼在哪，不说明在哪找。**

- 编号是连续的，中间不会跳；
- 每一段都以 `_` 结尾（最后一段除外），所以拼的时候不用猜；
- 第一段带开头、最后一段带结尾，首尾是锚定的，**别自己补括号**；
- 首尾之间谁先谁后，看编号就行 —— 你不需要"试"。

所以：**按"费劲程度"找，不要按编号顺序找。** 网页上点点就能看到的最简单，需要 clone 两个仓库的才费劲。

## 四、三条别做的事

1. **别在整个仓库里搜那个关键字符串。** 我确认过：搜不到。碎片是分开藏的，凑在一起才成立。
2. **别爆破、别穷举。** 对不上就是有块错了，回去重看，不要硬猜。
3. **别相信任何一份手抄的清单**（包括这份，也包括别人记的笔记）。**以你自己跑出来的命令输出为准** —— 交接笔记里手滑写错一个字符太正常了。

## 五、卡住了怎么办

按这个顺序自救，几乎能解决九成问题：

```bash
git log --oneline --all          # 我到底做过哪些事（不只当前分支）
git tag -n                       # 有没有我打过但你没注意的标记
git log --stat                   # 哪些文件被动过、被删过
git show <某个可疑的提交>          # 点进去看看那个提交到底改了什么
```

还是没有？那就换一个"面"想问题：**网页上除了代码，还有哪些标签页？** 每一个标签页背后都是一套独立的数据。

拼接规则和自查用的校验位不在仓库里（在仓库外的一个片段分享里），自己找一下；规则很短，一眼能看完。

## 六、最后

如果你把这题（就把它当一道题吧）做完了，回头再看一遍第二节那张表 ——
你会发现那六行其实就是**六种"删了但没删干净"**。这才是我想让你带走的东西：

> **数据不会因为你不想看见它而消失。**

祝好运。别把生产环境搞挂。
