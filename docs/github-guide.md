# GitHub 速查：这个平台上到底有哪些地方能放东西

> 组里新人手册。只讲**模块有什么用、能用它干什么、什么时候会用到**，不针对任何具体项目。
> 看完你应该建立这个概念：**"网页" ≠ "仓库"，"仓库" ≠ "历史"，"历史" ≠ "默认分支"。**

---

## 1. Code —— 仓库首页 / 文件树

- **是什么**：默认分支**当前那一刻**的快照。你点开的每个文件，都是某个 commit 里的一个版本。
- **能干什么**：读代码、看目录结构、切分支/tag 看不同版本、单文件点 `History` 看它自己的改动史、`Blame` 看每行是谁哪次改的、`Raw` 拿纯文本。
- **使用场景**：接手陌生项目、定位入口文件、Review 别人的目录结构。
- **坑**：右上角 `Download ZIP` 只给文件，**不给 `.git`**。要版本库得 `git clone` 或找别人打包的原件。

## 2. Commits —— 提交历史

- **是什么**：`git log` 的网页版，一条 commit = 一次快照 + 一条说明 + 作者/时间。
- **能干什么**：点进单条看 diff、按文件筛历史（`?path=`）、按作者筛、按时间筛、搜 commit message（注意：commit **搜索**和代码**搜索**是两套东西，前者要登录）。
- **使用场景**：追溯"这行代码什么时候进来的"、"这个文件被谁删的"。
- **坑**：网页默认只看当前分支的历史。**别的分支、tag、PR 上的提交，得切过去才看得到。**

## 3. Branches —— 分支

- **是什么**：指向某个 commit 的可移动指针。分支本身几乎不占空间，删了只是把指针删掉。
- **能干什么**：并行开发、临时试验、给不同环境留不同版本。
- **使用场景**：改功能不污染主线、给某次发布冻结一个版本。
- **坑**：**删分支 ≠ 删提交**。提交对象还在，只要还能从别的 ref 走到就一直能取到。

## 4. Tags —— 标签

- **是什么**：指向 commit 的**不可变**指针。分两种：
  - lightweight：只是个指针，没有独立内容；
  - annotated：有**自己的对象**，能写任意 message，签名也在这里。
- **能干什么**：标记版本 / 里程碑；annotated tag 还能当"小型公告板"用。
- **使用场景**：发版、标记交接点、标记某个"以后要回来看"的状态。
- **坑**：**Releases 页面只显示"建过 Release 的 tag"**，别的 tag 要去 `/tags` 或 `git tag -n` 才看得到；名字看起来一样的 tag 也可能被重新打过。

## 5. Releases —— 发行版

- **是什么**：一个 tag + 一段说明（release notes）+ 若干**附件**（asset）。
- **能干什么**：分发二进制/源码包/打包好的目录；给某次发布写 changelog；附件可以被替换。
- **使用场景**：给用户直接下载的东西、交付物归档。
- **坑**：附件、说明、tag 是**三个独立的东西**，删 Release 时要不要连 tag 一起删是个选项；网页的源码 ZIP 永远不带 `.git`。

## 6. Issues —— 问题 / 讨论

- **是什么**：项目内的异步讨论区。一条 Issue = 标题 + 正文 + 若干评论 + 标签/指派/状态。
- **能干什么**：报缺陷、提需求、答疑、发公告（置顶）；评论可以**编辑**，还能引用、贴代码块、上传图片。
- **使用场景**：新人问问题、记录决策过程、"这个坑以后再说"。
- **坑**：**评论被编辑过时，历史版本依然可见**（右上角 `edited`）。改了敏感内容不等于删掉；想彻底消失只能删评论，而删评论是不可逆的。

## 7. Pull Requests —— 合并请求

- **是什么**：一次"我这边的改动想合进你的分支"的申请，附带 diff、提交列表、评审意见、讨论。
- **能干什么**：代码评审、CI 预检、把讨论和改动绑在一起；可以关闭（不合）、合并（三种合并方式）。
- **使用场景**：协作开发的标准流程；也可以纯粹当"给某段代码开个话题"用。
- **坑**：
  - 列表页**默认只看 Open**，关闭的/合并的要点 `Closed` 才看得到；
  - 每个 PR 在服务端都有两个隐藏 ref：`refs/pull/<N>/head`（源分支顶端）和 `refs/pull/<N>/merge`（合并结果预览）——**源分支删了，这两个 ref 往往还在**，能直接 fetch。

## 8. Actions —— CI/CD

- **是什么**：仓库里的自动化。`.github/workflows/*.yml` 定义"什么时候跑、跑什么"，每次执行叫一个 **run**，run 里分 job / step，每步都有**日志**。
- **能干什么**：跑测试、构建、发布、定时任务、手动触发（`workflow_dispatch`）；日志里能看到命令和输出。
- **使用场景**：保证每次提交都能编译、自动跑测试、自动打包。
- **坑**：
  - **日志独立于仓库内容保存**（默认 90 天），删掉 workflow 文件、甚至重写历史，已有日志照旧在；
  - artifacts（产物）保留时间更短，且会过期；
  - 日志会**回显执行的命令**，所以"写进命令里的东西"和"命令输出"都会留痕。

## 9. Wiki —— 独立仓库

- **是什么**：`<owner>/<repo>.wiki.git` —— **另一个 Git 仓库**，页面就是里面的 `.md` 文件。
- **能干什么**：写长文档、手册、运维记录；有独立的分支和提交历史。
- **使用场景**：比 README 长的文档、团队约定、踩坑记录。
- **坑**：
  - `git clone` 主仓库**拿不到** wiki；
  - **删页面 ≠ 删历史**，`git log -p` 照样翻得到；
  - wiki 一个页面都没建过时，那个仓库**不存在**，必须先手建一次首页。

## 10. Gists —— 代码片段

- **是什么**：独立的小仓库，用来贴片段/日志/备忘，可以带多个文件。
- **能干什么**：快速分享、能被 clone、能版本化。
- **使用场景**：贴一段复现脚本、贴一段日志。
- **坑**：`secret`（默认）**不是私有**，拿到链接的人都能看，只是不出现在你的列表里；要真藏起来别用 gist。

## 11. Notes / 其他 ref —— 网页上根本看不到

- **是什么**：Git 原生的 `refs/notes/*`，可以给任意 commit 挂一条"注释"；另有 `refs/stash`、`refs/replace` 等。
- **能干什么**：给提交附加说明而不改动提交本身；暂存未完成的改动。
- **使用场景**：代码评审打标、临时存改动。
- **坑**：**默认既不随 `push` 上传，也不随 `clone` 下载**；只存在于某个具体目录（`.git/`）里。

## 12. 子模块 / LFS（各一句话）

- **Submodule**：仓库里记的是一个**别人的 commit SHA**，不是文件内容；`git clone --recursive` 才会把内容拉下来。
- **LFS**：大文件在库里只存一个**指针文件**（几十字节），真实内容在别处；只看 diff 会以为文件是空的。

## 13. 可见性与权限

- `private` / `public`：私有仓库的所有网页/接口都需要授权；**但一旦有内容流出去（clone、打包、附件下载），就再也收不回来。**
- **Deploy key**：绑在单个仓库上的 SSH key，只能拉那个仓库。
- **PAT / Token**：账号级凭据，**scope 决定它能干什么**（比如没有 `delete_repo` 就删不了仓库）。

## 一页速查表

| 模块 | 一句话 | 网页入口 | 命令行入口 |
|---|---|---|---|
| Code | 某一刻的文件快照 | 仓库首页 | `ls` |
| Commits | 提交历史 | `/commits/main` | `git log` |
| Branches | 可移动指针 | `/branches` | `git branch -a` |
| Tags | 不可变指针（annotated 带 message） | `/tags` | `git tag -n` / `git tag -l --format` |
| Releases | tag + 说明 + 附件 | `/releases` | `gh release list` |
| Issues | 讨论，评论可编辑 | `/issues` | `gh issue list` |
| PRs | 改动申请 + 隐藏 ref | `/pulls?q=is:closed` | `git fetch origin pull/N/head` |
| Actions | 自动化，日志独立保存 | `/actions` | `gh run list` / `gh run view --log` |
| Wiki | **独立仓库** | `/wiki` | `git clone <repo>.wiki.git` |
| Gists | 片段仓库（secret ≠ 私有） | `gist.github.com` | `gh gist list` |
| notes/stash | 网页看不到 | —— | `git notes list` / `git stash list` |

---

## 最后

这份手册**只列"哪里能放东西"，不告诉你东西放在哪**。
真正的用法是反过来的：**别人想藏什么，就会藏在上面这些地方。**

一个笨但有效的自查习惯：拿到一个"干净"的仓库，问自己一句 ——
> 说"我清理干净了"的人，是删了文件，还是删了提交？删了分支，还是删了日志？
